# Reports

Use for engineering status reports, incident reports, operational summaries, metrics pages, and written updates that benefit from structure and visuals.

Source examples:

- `11-status-report.html`: engineering weekly status with highlights, shipped table, velocity chart, and carryover.
- `12-incident-report.html`: incident report with severity metadata, timeline, root cause, impact table, and action items.

Useful template: `assets/templates/report.html`.

## Structure

- Put key metadata near the title: date, owner, severity, status, team, or reporting period.
- Use sections that match the report type, not a generic dashboard.
- Make critical facts scannable with chips, tables, timelines, and callout blocks.
- Include charts only when they clarify trend, impact, or progress.

## Patterns

- Status report: headline summary, highlights, shipped table, velocity/progress visual, carryover and risks.
- Incident report: incident metadata, summary, timeline, root cause, impact, action items with owners and due dates.

## Tone

- Use direct, operational language.
- Avoid celebratory or marketing copy.
- Separate known facts from follow-up work.
