# Exploration And Planning

Use for option comparison boards, design directions, approach tradeoffs, and implementation plans.

Source examples:

- `01-exploration-code-approaches.html`: three technical approaches with pros, cons, snippets, and recommendation.
- `02-exploration-visual-designs.html`: visual direction board with artboards, rationale, and a theme toggle.
- `16-implementation-plan.html`: execution plan with milestones, data flow, mockups, key code, risks, and open questions.

Useful template: `assets/templates/comparison-board.html`.

## Structure

- Open with a concise framing header: artifact type, user goal, and what decision this page supports.
- Present alternatives or phases as parallel sections so the reader can compare at a glance.
- Add a clear recommendation, decision, or next-step section when the page is meant to drive action.
- Include at least one visual artifact: code snippets, mockups, flow diagrams, matrices, timelines, or miniature UI states.

## Patterns

- For code approaches: use numbered cards with implementation snippets, strength/weakness chips, and a final recommendation panel.
- For visual directions: use an artboard grid with fixed-aspect stages and short rationale beneath each stage.
- For implementation plans: use numbered sections, milestone cards, flow SVGs, compact mockups, risk tables, and open questions.

## Avoid

- Treating exploration as a prose memo only.
- Hiding the final recommendation below too much setup.
- Using identical layouts for options that need visual comparison.
